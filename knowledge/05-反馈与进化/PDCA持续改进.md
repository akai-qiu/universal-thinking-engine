# 一、定义

Plan-Do-Check-Act 的循环改进框架：任何流程都能通过"计划→执行→检查→处置"的短周期循环持续逼近目标。

# 二、核心原理

改进的价值在循环速度而非单次深度。每个循环必须回到 Check（对照计划检查实际），跳过 Check 的 PDCA 退化成"做了又做"。Act 的产出要么是标准化（固化有效做法），要么是新计划（修正失效做法）。

# 三、解决什么问题

改进停留在口号；同一年犯同样的错；流程老化无人维护。

# 四、适用场景

- 已有明确流程或标准的持续优化
- 团队/个人的周、月度例行改进节奏

# 五、不适用场景

- 一次性任务——没有循环就没有 PDCA
- 环境剧烈变化期——计划生命周期短于循环周期时，改为滚动规划

# 六、使用方法

1. Plan：明确本轮改进的具体目标与判据（可测量）
2. Do：小范围执行，不做大爆炸式推广
3. Check：对照判据检查——数据说了算，不凭感觉
4. Act：有效则标准化固化，无效则回 Plan 修正
5. 缩短循环周期：周级循环胜过季度级

# 七、相关工具

戴明环、A3 报告、标准化作业、看板度量。

# 八、实际案例

丰田生产方式。见 `knowledge/06-案例库/`。

# 九、常见误区

- 循环太大（季度 Plan 季度 Check）——反馈延迟吃掉改进价值
- Check 环节靠主观感受——没有度量的 PDCA 是仪式
