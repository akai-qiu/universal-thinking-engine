# 一、定义

把单次经验提炼为可复用规则、把重复出现的情境识别为模式的转化过程。它是经验与智慧的分界线：经历 × 反思 × 沉淀 = 成长。

# 二、核心原理

沉淀的标准不是"有道理"，而是"下次能用"：规则必须具体到触发条件 + 动作（"遇到 X 情况做 Y"）。重复出现 ≥2 次的情境是模式，首次出现的是个案——过早规则化会用个案过拟合。

# 三、解决什么问题

经验年年攒、方法年年散；同一类问题每次都从头想；个人经验无法迁移复用。

# 四、适用场景

- 复盘之后的沉淀环节
- 发现"这事好像似曾相识"时的确认

# 五、不适用场景

- 只发生过一次的情境——先记案例，不升规则
- 高度依赖偶然变量的情境——规则化会固化错误归因

# 六、使用方法

1. 每次复盘末尾问：这次有没有产出"下次遇到 X 做 Y"级别的规则？
2. 新规则先进入实验状态（Experimental），被后续 ≥2 次真实任务复用有效后升为已验证（Validated）
3. 被新规则取代或证伪的旧规则降级（Deprecated），不删除——保留失败轨迹
4. 沉淀位置：通用规则进知识库，个人偏好进 memory，两者不混

# 七、相关工具

规则卡片格式（触发条件+动作+适用边界）、进化状态机（Draft/Experimental/Validated/Deprecated）。

# 八、实际案例

# 九、常见误区

- 沉淀成"感想集"（"要重视用户"）——不可执行的规则等于没沉淀
- 从单个案例直接升规则——过拟合，先在实验状态养两轮
