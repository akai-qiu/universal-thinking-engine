# 一、定义

把事物看作由相互关联的要素和反馈回路构成的整体，关注要素间的联动关系与动态演化，而非孤立的局部事件。

# 二、核心原理

系统的行为由结构决定：存量、流量、反馈回路（增强回路 R 与调节回路 B）和延迟共同产生长期行为模式。症状与病因常常不在同一处、不同时——头痛医头脚痛医脚的方案都是没看到回路。

# 三、解决什么问题

单点突破后崩塌；按下葫芦浮起瓢；短期见效长期恶化的方案；"可持续"如何落地。

# 四、适用场景

- 多要素互相影响、有反馈和滞后的问题（团队效能、增长、习惯养成、供应链）
- 需要设计"自我运转的机制"而非"一次性的动作"

# 五、不适用场景

- 简单因果、一次性的线性任务——画回路图是浪费
- 系统边界无法划清的纯哲学讨论

# 六、使用方法

1. 画出关键要素和箭头：A 增加导致 B 增加还是减少？
2. 识别回路：增强回路（滚雪球）找飞轮，调节回路（自我修正）找天花板
3. 找杠杆点：通常是信息流、激励结构或回路连接处，而非单个要素的数值
4. 延迟警惕：今天没效果不等于方向错，今天见效不等于长期对

# 七、相关工具

因果回路图、存量流量图、飞轮效应、系统动力学（Forrester/Meadows）。

# 八、实际案例

亚马逊飞轮（低价→体验→流量→卖家→规模→更低成本）；见 `knowledge/06-案例库/`。

# 九、常见误区

- 把要素清单当系统分析——没有回路和延迟就不是系统思维
- 只画增强回路自我感动；调节回路（哪里会刹车）往往更重要

# 十、相关知识

系统架构与机制设计（把回路变成现实机制）、适应性与反脆弱性。

# 十一、参考来源

德内拉·梅多斯《系统之美》、彼得·圣吉《第五项修炼》。
