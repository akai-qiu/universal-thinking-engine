# 一、定义

把模糊的大问题按明确维度拆成互相独立、合起来穷尽的子问题（MECE），使每个子问题可单独判断与处理。

# 二、核心原理

拆解的质量取决于维度选择：好的维度让子问题互不重叠（不重复劳动）且加总覆盖全部（不遗漏）。金字塔结构自顶向下展开，每一层都是上一层问题的回答。

# 三、解决什么问题

杂乱无章、抓不住本质、想到哪做到哪；多人协作时任务边界不清。

# 四、适用场景

- 任何需要"把大目标拆成可执行单元"的场合（M/L 级任务的拆解阶段）
- 需要向他人清晰陈述复杂事物的场合

# 五、不适用场景

- 问题本身只有一两个要素——过度拆解是负担
- 探索性发散阶段（创造性思维先行，结构化收尾）

# 六、使用方法

1. 先写下顶层问题的一句话表述（模糊则先做问题定义）
2. 选择拆解维度：流程（按时间）、构成（按部分）、逻辑（按条件）——同一问题可用不同维度各拆一次，对比哪次 MECE 更干净
3. 检查每个叶子节点能否回答"怎么判断它做没做到"——回答不了的是伪需求

# 九、常见误区

- 把拆解清单当分析结果——拆完不验证叶子节点，等于没拆
- 维度混层（有的按流程拆、有的按部门拆），导致重叠和遗漏
