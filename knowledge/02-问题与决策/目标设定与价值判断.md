# 一、定义

把确认后的需求转成可判断成败的目标体系，并对多个目标排出价值顺序——因为资源永远不够同时追求所有目标。

# 二、核心原理

好目标有两个特征：可判断（怎么算做到，有明确的验收方式）与有权重（多个目标冲突时知道保哪个）。不可判断的目标是愿望，无权重的一组目标等于没有目标。

# 三、解决什么问题

目标漂移（做到一半换标准）；多目标冲突时反复摇摆；用忙碌掩盖方向缺失。

# 四、适用场景

项目启动、季度/年度规划、目标树叶子节点的验收定义。

# 五、不适用场景

- 探索性任务早期——先设"学习目标"（要回答什么问题）而非"结果目标"

# 六、使用方法

1. 每个目标写成"可观察的状态变化 + 判断方式 + 时间点"
2. 终局倒推：想象 5-10 年后的理想终局，今天的目标是不是通向它的一步？
3. 强制排序：如果只能保一个目标，保哪个？写出取舍，让冲突提前暴露
4. 区分「承诺目标」（必须达成）与「意向目标」（尽力而为）——混写会让意向目标绑架资源

# 七、相关工具

OKR（目标-关键结果）、SMART、逆向工作法（贝佐斯 PR/FAQ）、终局思维。

# 八、实际案例

贝佐斯要求项目立项前先写虚构的新闻稿（PR/FAQ），站在终局质询项目价值。见 `knowledge/06-案例库/`。

# 九、常见误区

- 目标全是动词短语没有判断标准（"提升用户体验"）
- 排序只在嘴上，预算和时间却平均分配——真实权重看资源分配
