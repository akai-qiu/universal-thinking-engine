# 一、定义

在有限资源下对任务/方案排序的方法：用显式框架代替直觉，使取舍可见、可辩论、可复查。

# 二、核心原理

直觉排序会被新鲜度、说服力和噪音干扰。显式框架（打分矩阵、价值/成本二维）不产生更优答案，但让权重假设暴露出来——假设错了可以改框架，直觉错了只能吵架。

# 三、解决什么问题

什么都想做结果什么都做不好；排序被嗓门大的人主导；决策理由事后无法复盘。

# 四、适用场景

- 多任务抢同一批资源
- 多方案对比选型
- 需求积压的筛选

# 五、不适用场景

- 候选项 ≤2 且差异明显——直接判断，框架是仪式
- 权重本身高度不确定时——先解决权重问题（回到目标设定）

# 六、使用方法

1. 列出候选与评估维度，维度来自目标（不是"通用维度清单"）
2. 与用户/团队对齐权重——权重对齐比打分对齐更重要
3. 打分排序，再人工过一遍排序结果的合理性（框架输出是输入，不是答案）
4. 记录排序理由——为后续复盘留证据

# 七、相关工具

Eisenhower 矩阵（重要/紧急）、RICE（Reach/Impact/Confidence/Effort）、加权决策矩阵、Kano 模型。

# 九、常见误区

- 给维度打分时假装精确（3.7 分）——量级判断比小数点诚实
- 框架输出直接执行不复查——框架暴露假设，人负责裁决
