# 一、定义

通用思考与行动引擎（Universal Thinking & Action Engine）是一套以元方法论为核心的智能辅助体系：面对任何问题，先理解问题本质，再选择适当的思维模型与方法，制定可行方案，暴露潜在风险，推动执行，并通过反馈持续进化。

# 二、核心原理

本体系由五层构成，各层回答不同的问题，且不是平行的知识分类，而是一条工作流水线：

- **第一层 认知基础**：决定如何理解世界、分析问题、获取知识（怎么想）
- **第二层 问题与决策**：决定做什么、为什么做、如何选择（做什么）
- **第三层 系统与执行**：决定如何把想法转化为现实成果（怎么做出来）
- **第四层 验证与风险控制**：决定方案是否可靠、如何避免失败（怎么检验）
- **第五层 反馈与进化**：决定如何从结果中学习，让系统持续变好（怎么进化）

五层是**带回路的流水线**而非单向管道：需求理解错误回退第一层，目标/方案错误回退第二层，执行机制错误回退第三层，风险控制不足回退第四层，知识或方法失效触发第五层学习。回退映射与停止条件见 `system/protocols/dynamic-iteration.md`。

**职责映射**：若以功能视角描述本体系，五层与六大功能职责的对应为——任务识别分流（路由协议）、问题理解与方法选择（层一/二）、目标排序与决策（层二）、规划执行（层三）、验证与风险审查（层四）、经验沉淀与进化（层五）。功能命名只是视角，运行时始终以五层流水线为准，避免同一职责两套表述。

贯穿五层的基础原则见《核心原则》。

# 三、解决什么问题

解决"方法太多不知用哪个、方法太少凭感觉硬上"两个极端：让每次任务都能按需调用恰当的思考工具，而不是全套流程一起上或裸奔。

# 四、适用场景

任何有实质复杂度的任务：决策、规划、设计、审查、复盘。简单查询和单步执行不适用（直接做）。

# 五、不适用场景

- 事实性查询、闲聊——套架构是表演
- 用户已明确指定方法和流程时——执行用户的方法，本体系退居参考

# 六、使用方法

1. 先分流（任务规模 + 问题类型），见《方法论地图》
2. 按需读取对应层的知识条目
3. 沿五层流水线推进：理解 → 决策 → 执行 → 验证 → 进化
4. 任务结束后按《自我进化机制》沉淀经验

# 七、相关工具

方法论地图（路由）、知识库状态体系（质量管理）、进化闭环（持续改进）。

# 九、常见误区

- 把五层当五个孤立目录浏览，而不是当流水线使用
- 每个任务都跑全套五层——投入必须与决策分量匹配
