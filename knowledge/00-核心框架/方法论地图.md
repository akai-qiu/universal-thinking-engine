# 一、定义

本 skill 的路由入口：先识别任务规模与问题类型，再决定调用哪些方法、读取哪些知识条目。这是元方法论的核心——不是懂方法，而是懂得选择、组合、调整方法。

# 二、核心原理

**双维分流**，两个维度都要看：

**维度一：任务规模**——五维风险评估（可逆性、影响范围、不确定性、潜在损失各 0-2 分求和，时间敏感性不参与求和）：

| 级别 | 判据 |
|------|------|
| S | 总分 ≤ 1：直接做/直接答，不走流程 |
| M | 总分 2-5：轻量流程（重述→路径+权衡→快速红队→建议+再评估信号） |
| L | 总分 ≥ 6：完整五层流水线 |

**强制升级条件**（防高风险被低分抵消，无视总分直接定级）：可逆性 = 2 或潜在损失 = 2 → 直接 L；影响范围 = 2 且不确定性 ≥ 1 → 不低于 M；任两维同时 = 2 → 直接 L。时间敏感性只压缩流程深度，不改变级别。评分细则见 `system/protocols/task-routing.md`。

**维度二：问题类型 → 重点调用能力**

| 遇到的事 | 重点调用的能力 |
|----------|----------------|
| 设计新 UI 产品 | 问题定义与需求洞察、创造性思维、系统架构、渐进式实施 |
| 规划长期学习计划 | 目标设定与价值判断、渐进式实施与迭代、复盘 AAR |
| 选择一个工具/方案 | 问题定义、信息素养与证据判断、机会成本与权衡取舍 |
| 建立工作流程 | 系统架构与机制设计、资源配置与瓶颈管理、PDCA |
| 重大决策 | 概率思维、战略思维、事前验尸、风险管理 |
| 解决复杂难题 | 第一性原理、结构化思维、系统思维、对抗式审查 |
| 评估他人方案 | 批判性思维、事前验尸、逆向思维、信息素养 |
| 复盘成败 | 复盘 AAR、模式识别与知识沉淀、元认知与认知修正 |

# 三、解决什么问题

解决"所有方法一起上"（简单事复杂化、输出冗长）和"没有方法硬上"（凭感觉、漏风险）两个极端。

# 四、适用场景

每次触发本 skill 后的第一动作。定级结果要告知用户，允许用户纠正。

# 五、不适用场景

- 用户点名要某个具体方法/视角时，直接用，跳过路由
- S 级任务——分流本身就是它的处理方式

# 六、使用方法

1. 先按五维评分定级（细则见 system/protocols/task-routing.md），再认类型
2. 按类型表读取 2-4 个对应知识条目，不读全库
3. 拿不准规模时问一句："这个决定可逆吗？影响面多大？"——这一问本身是方法论的一部分
4. 话题听起来大不一定是 L（探索性草稿可能只是 M）；听起来小不一定是 S（不可逆的生产操作就是 L）

# 七、相关工具

总体架构（五层流水线）、事前验尸（L 级审查）、复盘 AAR。

# 九、常见误区

- 只看话题热度定级，不看可逆性和影响面
- 路由后仍把选中条目之外的方法也塞进来——路由的意义就是舍弃
