# 一、定义

方案设计中对"谁来执行、他们为什么愿意"的检验：激励是否对齐、阻力是否被低估、习惯是否被尊重。防止产生"纸上谈兵"的高冷方案。

# 二、核心原理

要求他人"克服惰性、违反自身利益"的方案会在执行层死掉。阻力最小路径（Path of Least Resistance）：行为跟随环境的摩擦力走，不跟宣言走。改变行为靠改环境与激励，不靠说服。

# 三、解决什么问题

方案逻辑完美但没人执行；协作方口头答应、行动拖延；自己给自己立的 flag 屡立屡倒。

# 四、适用场景

- 方案涉及任何配合方（包括未来的自己）时
- 习惯养成、流程推行、跨团队协作

# 五、不适用场景

- 紧急军令状态——非常手段可临时压过激励设计，但不可持续，事后必须补

# 六、使用方法

1. 激励对齐检查：每个配合方，"按方案行动"对他们自身有什么好处？没有好处 = 潜在阻力源，回设计阶段改机制
2. 首步最小化：把启动动作拆到"今天就能完成、低到不可能拖延"的粒度
3. 环境设计：让目标行为更省力（工具、默认值、物理位置），让干扰行为更费力
4. 承诺与检查点：约定具体时间与验收，公开承诺提高执行率

# 七、相关工具

激励对齐分析、习惯回路（提示-行为-奖励）、默认选项设计、两分钟法则。

# 九、常见误区

- 用"加强沟通"解决激励冲突——沟通改变认知，激励改变行为，两者不是一回事
- 对自己例外：制定方案时把自己想象成理性机器，执行时才发现自己也是人
