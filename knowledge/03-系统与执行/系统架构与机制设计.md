# 一、定义

把目标转成能自我运转、可持续演进的机制与结构，而不是依赖持续人力的动作清单。设计的是"让正确的事自动发生"的系统。

# 二、核心原理

好的机制利用反馈回路自动修正（自愈），坏的系统靠人肉兜底（随人力耗尽而崩）。飞轮效应：找到"每转一圈都为下一圈积累势能"的增强回路。

# 三、解决什么问题

方案靠意志力维持（人一松懈就回退）；单点突破后崩塌；团队规模扩大后流程失效。

# 四、适用场景

- 需要长期运转的流程（质量保障、内容生产、增长引擎）
- L 级方案的设计阶段

# 五、不适用场景

- 一次性任务——设计机制是浪费，直接做
- 机制本身带来的固定成本超过收益的小规模场景

# 六、使用方法

1. 画回路：期望行为由什么激励维持？非期望行为由什么漏洞允许？
2. 自愈检查：如果没人盯，这个机制 3 个月后还在运转吗？靠什么信号发现问题？
3. 飞轮检查：每轮运转是否为下一轮积累资产（数据、信任、内容、技能）？
4. 失效模式：机制最常见的三种失效方式是什么？各自的自动报警在哪？

# 七、相关工具

飞轮设计、检查表（防遗忘机制）、自动化触发器、 incentive alignment。

# 八、实际案例

亚马逊飞轮；桥水的决策算法化。见 `knowledge/06-案例库/`。

# 九、常见误区

- 机制越建越复杂，最终没人遵守——机制的服务对象是人，复杂度上限由人性决定
- 只设计成功路径，不设计失效报警
