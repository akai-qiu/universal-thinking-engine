# 一、定义

把拆解后的目标树转成有顺序、有依赖、有责任、有节点的任务网络，并对工期做现实的估算。

# 二、核心原理

任务的三个必要元数据：依赖关系（什么必须先完成）、完成定义（DoD：做到什么算完成）、负责人。缺任何一项的任务会在执行期变成扯皮点。估算遵循平方根规律：复杂度是线性时，工期是平方关系。

# 三、解决什么问题

任务之间的依赖在执行中才暴露；"完成"标准不清导致的返工与扯皮；工期估算过于乐观。

# 四、适用场景

- M/L 级任务的执行准备阶段
- 多人协作、多依赖的项目

# 五、不适用场景

- 探索性/研究性任务——先设学习目标，产出本身不可预先拆解

# 六、使用方法

1. 每个任务卡片四要素：产出物、DoD、依赖、负责人
2. 排依赖图，找关键路径——关键路径上的任务延误直接延误整体
3. 估算打缓冲：经验估 × 1.5~2，或用三点的 PERT 加权
4. 定检查点节奏：固定周期对进度（如每周），而非"做完再说"

# 七、相关工具

WBS、关键路径法、看板、DoD（Definition of Done）、PERT。

# 九、常见误区

- 任务颗粒度失控：太粗（"完成 v1"）或太细（管理成本超过执行成本）
- 只排日期不管依赖——日期排得再好，依赖断了全盘皆输
