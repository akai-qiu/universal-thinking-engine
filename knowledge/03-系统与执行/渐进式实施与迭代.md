# 一、定义

把大交付切成 2-4 个阶段，每阶段产出可验证的成果并设决策门（准入/退出条件），不可逆动作尽量推迟到最后阶段。

# 二、核心原理

每提前一个阶段获得真实反馈，就能少花一倍的返工成本。MVP 的 M 是"足以验证关键假设的最小版本"——它的产出物是学习，不是产品。分期若没有决策门，只是把同一件事做三遍的拖延。

# 三、解决什么问题

大爆炸式交付的孤注一掷；方向错了却发现时已投入 90%；好高骛远无法启动。

# 四、适用场景

- L 级任务的执行规划
- 关键假设未经验证的新方向

# 五、不适用场景

- 方案已充分验证、需求明确的成熟模式——分太多期徒增协调成本
- 不可拆分的原子性交付

# 六、使用方法

1. 找出最危险的关键假设——整个方向押在它上面
2. 设计第一阶段专门验证该假设，产出物是"假设成立/证伪"的答案
3. 每阶段写明：可验证产出、进入下一阶段的准入条件、止损点（什么情况放弃）
4. 不可逆动作（签约、上线、公开承诺）放到验证链的末端

# 七、相关工具

MVP、决策门（Stage Gate）、假设验证板、灰度发布。

# 八、实际案例

SpaceX 迭代式试飞——把失败设计进流程，每炸一次买一层认知。见 `knowledge/06-案例库/`。

# 九、常见误区

- 把 MVP 做成"功能阉割版"而不是"假设验证器"——验证不了假设的最小产品没有学习价值
- 分期而没有决策门——只是把死亡过程拉长
