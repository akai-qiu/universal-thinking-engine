# 一、定义

把审查阶段发现的风险转为可执行的保护措施：分级登记、明确触发信号、设计应对路径，并保留与主路径不同源的退路。

# 二、核心原理

风险清单本身没有保护力，"信号 + 应对"才有。有效预案三要素：明确的触发信号（什么情况启动）、明确的动作（谁做什么）、不同源的退路（Plan B 不能与 Plan A 死于同一资源断供）。

# 三、解决什么问题

风险列了却没人管；危机来了才发现预案没绑定资源；Plan A 和 Plan B 一起死。

# 四、适用场景

- L 级方案的审查收尾与执行准备
- 高外部依赖、长周期项目

# 五、不适用场景

- 每个风险都做全套预案——按杀伤力分级，只对高危项做预案，其余监控

# 六、使用方法

1. 风险登记表：风险描述 / 可能性 / 杀伤力 / 应对策略（规避/缓解/转移/接受）/ 触发信号 / 负责人
2. "接受"也是合法策略——但要显式写出"接受"，不允许沉默漏掉
3. 高危风险配 Plan B，并做同源检查："如果 X 资源断供，Plan B 还活着吗？"
4. 设定期复审：风险随环境变化，登记表是活文档

# 七、相关工具

风险登记表、风险矩阵（可能性×杀伤力）、预案触发器。

# 九、常见误区

- 预案写在文档里，资源没有预留——没有预算的 Plan B 是许愿
- 只识别外部风险，漏掉内部风险（关键人流失、动力衰退、预算被挪用）
