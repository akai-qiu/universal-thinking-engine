# 一、定义

设立独立的攻击方（红队）与防御方（蓝队）进行实战化对抗：红队模拟真实的攻击逻辑（黑客、竞争对手、极端用户），全方位检验现有防线。

# 二、核心原理

红队的价值来自独立性：不由建设者兼任、不与建设绩效绑定。物理世界的破坏性测试（SpaceX 炸火箭）与数字世界的渗透测试是同一原理——把失败成本买在可控的测试场，而不是不可控的实战。

# 三、解决什么问题

防线"看起来完备"但未经实战；建设者的自查盲区；危机响应能力从未演练。

# 四、适用场景

- 安全渗透测试、容灾演练
- 高对抗性环境（竞争市场、公关危机）的预案检验
- L 级系统的上线前检验

# 五、不适用场景

- 小规模低风险系统——对抗成本超过防护价值
- 无复盘机制的组织——红队发现的问题没人修，白测

# 六、使用方法

1. 明确红队目标与规则（允许的攻击范围、判胜标准）
2. 红队独立运作：不参加建设讨论，只拿到与真实攻击者等价的信息
3. 实施攻击/演练，记录每一个突破点与防御响应时间
4. 蓝队复盘修复 → 下一轮再测。对抗的价值在循环次数，不在单轮输赢

# 七、相关工具

渗透测试框架、混沌工程（Chaos Engineering）、Tabletop 演练、故障注入。

# 八、实际案例

SpaceX 快速迭代与破坏性测试；Netflix Chaos Monkey。见 `knowledge/06-案例库/`。

# 九、常见误区

- 让建设者自演红队——屁股决定结论，独立性没了对抗就变成表演
- 演练结果不闭环——发现 20 个漏洞修 3 个，红队沦为成本
