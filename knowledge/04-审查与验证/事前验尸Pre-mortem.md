# 一、定义

方案落地前，假设"一年后这个项目彻底失败了"，全员倒推失败原因的预演技术。与复盘（事后分析）相对，验尸发生在事前——死者的尸体是方案自己。

# 二、核心原理

"未来已经失败"的设定解除了乐观压力：人更容易说出坏消息（"反正已经失败了"），从而暴露平时不敢提的风险。Gary Klein 的研究显示它能把风险识别数量显著提高。

# 三、解决什么问题

集体乐观与沉默螺旋（每个人都看到问题但都以为别人没看到）；风险清单永远太短；失败原因只能在失败后才知道。

# 四、适用场景

- L 级方案的审查阶段（必做）
- 项目启动会、重大承诺（签约/上线/公开宣布）之前
- 团队气氛过度乐观时的清醒剂

# 五、不适用场景

- S 级决策——成本不匹配
- 方案还在发散探索期——先收敛再验尸

# 六、使用方法

1. 设定："现在是 2027 年 11 月，这个项目刚刚彻底失败"
2. 每人/每视角独立写 3-5 条死因（独立写再汇总，防止互相带偏）
3. 按"可能性 × 杀伤力"排序，只对前 2 项做深入应对
4. 每个高危死因产出：缓解措施 / Plan B / 明确接受（三选一，不许沉默）
5. 有结构性问题的回设计阶段，不打补丁

# 七、相关工具

失败分类框架（需求/技术/资源/人/时机）、风险登记表。

# 八、实际案例

见 `knowledge/06-案例库/`。

# 九、常见误区

- 死因写得太抽象（"执行不力"）——死因必须具体到可采取行动
- 只列风险不做应对——清单本身没有保护力
