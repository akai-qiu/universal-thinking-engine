# 一、定义

从"作者"切换为"做空者"的审查模式：不以证明方案可行为目标，而以寻找它的死法为目标。正向建设回答"怎么建"，对抗式审查回答"怎么会死"。

# 二、核心原理

作者视角天然有确认偏误——自己写的方案自己看不出洞。制度化的对立视角（红队/魔鬼代言人）把"被别人发现漏洞"提前到"自己主动暴露漏洞"，成本从失败转移到审查。

# 三、解决什么问题

自我验证的盲区；团队集体乐观；方案在未经攻击的情况下直接投产。

# 四、适用场景

- L 级方案的审查阶段（完整 Pre-mortem + 反例清单）
- M 级的快速红队：对推荐路径至少找出 1 个致命假设或反例
- 重要文档/代码/决策发布前

# 五、不适用场景

- S 级任务——审查成本超过标的本身
- 探索早期还在发散——过早攻击杀死未成熟的想法

# 六、使用方法

1. 切换视角声明："现在我是做空者，任务是让这个方案失败"
2. Pre-mortem：假设一年后彻底失败，倒推 3-5 个最可能的死因，按可能性 × 杀伤力排序
3. 假设审计：列出方案依赖的关键假设，逐条问"如果它是错的会怎样"——最危险的是没人意识到是假设的那些
4. 魔鬼代言人自检：用一句话陈述"反对这个方案的最强理由"。写不出来 = 审查没做
5. 通过标准：每个高危死因有缓解措施或 Plan B，或明确"接受此风险"（写出来，不是漏掉）

# 九、常见误区

- 审查发现了结构性问题却只打补丁——应回退重设计
- 攻击得手后全盘推翻方案——按"可修复/结构性"区分处理
