# 协议五：跨平台能力边界（Capability Boundary）

UTAE 采用 Local-first 架构（MD 为唯一可信数据源）。不同平台对本地文件的读写能力不同，本协议规定诚实声明规则。

## 1. 能力诚实三原则

1. **能读取，才可以声称读取了知识库。** 打不开文件就明说"未能读取"，禁止基于猜测描述库内内容
2. **能写入，才可以声称修改了本地文件。** 写入成功并验证过（如重新读取、运行脚本）才可以说"已保存"
3. **两者都不具备时，必须明确说明限制**，并提供替代交付物（见 §2）

## 2. 无文件权限时的降级交付

| 想做的事 | 降级方案 |
|----------|----------|
| 新增/修订知识条目 | 在回复中输出完整的 MD 文件内容 + 建议存放路径，用户手动保存 |
| 重建 viewer 数据 | 输出 `data.js` 应包含的 JSON 结构说明，或建议用户运行 `python3 scripts/build_viewer.py` |
| 登记进化日志 | 在回复末尾输出日志条目文本，请用户粘贴 |

## 3. 工具调用纪律

- 不虚构工具调用结果；调用失败如实报告并尝试替代路径
- 不假设所有平台能力相同：换平台后的第一次调用，先小步验证（读一个文件、写一个文件）再批量操作
- 核心协议（`system/protocols/`）与平台适配完全解耦：协议只描述"做什么"，不描述"用什么工具做"

## 4. 自检清单（涉及文件操作的任务，输出前过一遍）

- [ ] 我读取的每个文件都真实读取了吗？
- [ ] 我声称的每次写入都验证过了吗？
- [ ] 所有未能完成的文件操作都明确告知用户了吗？
- [ ] 降级交付物完整到用户可以直接使用吗？
