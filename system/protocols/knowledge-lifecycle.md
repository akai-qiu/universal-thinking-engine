# 协议四：知识生命周期（Knowledge Lifecycle）

知识的产生、验证、发布是三个独立环节。本协议规定从想法到正式知识的完整路径与晋级标准。

## 1. 状态机

```
Draft → Experimental → Pending Review → Validated
                ↑            |
                └── 未通过审核 ┘
                （退回实验或进入 Deprecated）
```

| 状态 | 含义 | 是否允许正式调用 |
|------|------|------|
| draft | 新发现，尚未整理 | 仅供参考，需标注 |
| experimental | 正在真实任务中验证 | 有条件调用，需标注 |
| pending_review | 已提交，等待用户审批 | 有条件调用，需标注 |
| validated | 已通过验证与审批 | 正常调用 |
| deprecated | 已过时或被取代 | 禁止默认调用 |

## 2. 晋级标准（五问，全部满足才可送审）

1. 是否经过**真实任务**验证（不是思想实验）？
2. 是否具备**重复性**（不同情境下有效，不是一次性巧合）？
3. 是否明确了**适用条件和失效边界**（什么时候不成立）？
4. 是否通过了**反例审查**（主动找过它失败的情形）？
5. 是否比现有知识产生**增量价值**（不是已有条目的换皮）？

## 3. 关键修正：两次成功 ≠ 有效

同一规则在 ≥2 次真实任务中复用有效，只是**晋级候选条件**（进入 Pending Review 的资格），不能直接代表知识有效。送审材料必须同时附上：适用条件、失效边界、至少一个曾 considered 的反例。

## 4. 权限与纪律

- **AI 可自主**：学习、检索、整理、记录案例与实验、提出改进提案（放入 `knowledge/08-待审核知识/`）
- **AI 不可自主**：修改核心规则与正式知识条目、发布 validated、物理删除任何条目——这些必须经用户审批
- **废弃保留**：Deprecated 条目永不静默删除，保留原因与被取代指向（`knowledge/09-废弃知识/`）
- **变更登记**：每一次状态变更写入 `evolution/版本变更日志.md`
- **数量不是指标**：禁止为增加条目数量而入库。知识库的价值在于每条都被真实引用过

## 5. 与目录的对应

- draft / experimental → `knowledge/07-实验库/`
- pending_review → `knowledge/08-待审核知识/`
- validated → `knowledge/01` ~ `05` 正式目录
- deprecated → `knowledge/09-废弃知识/`
