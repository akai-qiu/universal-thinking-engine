# 协议三：动态迭代与回退（Dynamic Iteration）

五层流水线不是单向传送带。任何一层发现上游的问题，必须回退到对应层，而不是带着错误继续往下走。

## 1. 回退映射

| 失效信号 | 典型表现 | 回退目标 |
|----------|----------|----------|
| 需求理解错误 | 用户目标与产出持续错位；验收标准无法定义 | 回到**第一层**（认知理解）重新定义问题 |
| 目标或方案错误 | 目标权重反复摇摆；方案对比中取舍写不清；关键假设被证伪 | 回到**第二层**（问题决策）重新排序目标或重设计 |
| 执行机制错误 | 依赖断裂；估算连续失准；配合方不执行（激励错位） | 回到**第三层**（系统执行）改机制，不在执行层喊口号 |
| 风险控制不足 | 出现未登记的高危风险；预案失效 | 回到**第四层**（验证审查）补充 Pre-mortem 与预案 |
| 知识或方法失效 | 路由选的方法不适用；知识条目的边界与现实冲突 | 触发**第五层**（反馈进化）：按知识生命周期降级或修订，不硬撑 |

## 2. 回退纪律

- 回退时**明确声明**："在第 N 层发现 X 问题，回退到第 M 层"，让用户知道系统状态
- 回退修正的是结构问题——如果只是局部小缺陷，允许打补丁，但要说明为什么不算结构性
- 每次回退的原因登记到 `evolution/学习日志.md`（同一类问题反复出现是知识库缺口信号）

## 3. 停止条件（防无限循环与无意义分析）

出现以下任一情况，停止迭代并向用户报告：

1. **同层回退 ≥ 2 次**：同一层两次回退仍不能收敛，说明问题在当前框架之外（需求本身矛盾、信息根本不足、或需要用户的意志决断）。停止分析，把矛盾点摆清楚，升级为用户决策
2. **信息饱和**：新信息不再改变结论。继续收集是伪装成勤奋的拖延
3. **时间盒到期**：约定分析时间用尽，带着当前最优结论 + 未决问题清单交付
4. **边际收益趋零**：第 N 轮迭代的改进幅度明显小于第 N-1 轮

## 4. 允许正向跳跃

不是所有任务都要从第一层线性走完。分流后如果问题定义清晰、方案明确，允许直接进入第三层（执行）或第四层（审查）。跳跃时声明跳过了什么、为什么可以跳。
