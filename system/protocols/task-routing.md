# 协议一：任务分流（Task Routing）

运行入口协议。每次触发 UTAE 后先执行本协议，再按结果路由。

## 1. 五维风险评估

对任务按以下五个维度打分（0 = 低，1 = 中，2 = 高）：

| 维度 | 0 分 | 1 分 | 2 分 |
|------|------|------|------|
| 可逆性 | 完全可逆，撤销成本≈0 | 可逆但撤销有成本 | 不可逆，或撤销代价极高 |
| 影响范围 | 只有自己 | 自己 + 少数人/单一系统 | 团队/多个系统/对外 |
| 不确定性 | 路径明确 | 有 2-3 条路径需选择 | 关键假设未验证、结果难预测 |
| 潜在损失 | 几乎无 | 时间/金钱损失可控 | 重大金钱、声誉、数据、安全损失 |
| 时间敏感性 | 不急 | 有节奏要求 | 紧急到影响流程选择 |

## 2. 分级规则

计算前四维之和（时间敏感性不参与求和，见 §4）：

- **S 级**：总分 ≤ 1
- **M 级**：总分 2-5
- **L 级**：总分 ≥ 6

## 3. 强制升级条件（防高风险被低分抵消）

以下条件触发时，无视总分直接定级：

- 可逆性 = 2（不可逆）→ **直接 L**
- 潜在损失 = 2 → **直接 L**
- 影响范围 = 2 且不确定性 = 1 以上 → **不低于 M**
- 任两维同时 = 2 → **直接 L**

设计意图：一个"可逆性低但其他都低"的任务（如删除生产数据）总分可能只有 4，却绝不能按 M 级轻率处理。

## 4. 时间敏感性的特殊用法

时间敏感性**不改变任务级别，只改变流程深度**：

- 时间敏感性 = 2 且定级为 L → 用压缩流程（重述 → 路径权衡 → 快速红队 → 决策），跳过完整 Pre-mortem，但必须在时间允许后补一次复盘
- 紧急不等于重大：时间敏感的 S 级任务仍然是 S 级，直接做

## 5. 不确定时的处理

1. 拿不准某维打分时，问用户一个具体问题（如"这个决定可逆吗？影响面多大？"）——这一问本身是方法论的一部分
2. 仍无法判断时，**按更高一级处理**（宁可过度审视，不可漏掉风险），并告知用户定级偏保守
3. 定级结果必须在回复开头明示（例：「M 级决策，用轻量流程」），用户随时可以纠正，纠正后按新级别重跑

## 6. 反拖累条款

S 级任务禁止套用任何协议结构。直接回答或执行；最多一句风险提示。分流的意义就是让简单任务零负担。
